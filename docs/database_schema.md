# Локальная схема D1

Миграция `worker/migrations/0001_initial_schema.sql` создаёт основу хранения пользователей, источников, публикаций, истории изменений, уведомлений и курсоров опроса. Миграция `0002_ingestion.sql` добавляет снимки публикаций и служебные таблицы безопасного многошагового импорта; `0003_ingestion_safety.sql` добавляет SQLite guard-триггеры и счётчик успешных записей checkpoints; `0004_historical_baseline_gate.sql` блокирует incremental-запуск для источника до завершения его первого полного historical-запуска. Уже применённые миграции не изменяются.

| Таблица | Назначение и ограничения |
| --- | --- |
| `users` | `telegram_id` как PK; `language` — `uk`/`ru`; флаги уведомлений — `0`/`1`. |
| `sources` | Справочник источников с уникальным `code`; миграция добавляет `folketinget` и `hoeringsportalen`. |
| `publications` | Снимок публикации; уникальность `(source_id, external_id)`, внешний ID сохраняется как текст. `relevance`: `DIRECT`, `POTENTIAL`, `IRRELEVANT`. |
| `publication_events` | История событий с уникальным `event_key`; `notify_eligible=0` позволяет импортировать историю без уведомлений. |
| `notifications` | Очередь доставки с уникальностью `(telegram_id, event_id)` и статусами `PENDING`, `SENDING`, `SENT`, `FAILED` (`SENDING` добавлен миграцией 0005 для атомарного claim). |
| `source_states` | Независимый checkpoint на каждую пару `(source_id, stream_key)`. |
| `source_ingestion_baselines` | Источник допускается к incremental-синхронизации только после атомарного успешного COMMITTED historical-запуска. |
| `ingestion_runs` | Жизненный цикл импорта, базовые/предложенные checkpoints, счётчики, блокировки и итоговый статус. Частичный уникальный индекс разрешает только один незавершённый запуск на источник. |
| `ingestion_batches` | Хеш и размер принятого пакета; PK `(run_id, batch_index)` обеспечивает идемпотентные повторы. |
| `ingestion_staging` | Проверенные записи пакета до долговременной обработки; PK `(run_id, source_id, external_id)` исключает дубли внутри запуска. |

В `publications` миграция 0002 хранит исходные метаданные, нормализованный снимок, снимок связей, версию правил, полноту источника, исторический флаг и диагностики. В `publication_events` добавлен JSON-снимок изменения. Структурированные поля записываются как канонический JSON TEXT для стабильного сравнения.

Все временные значения — `TEXT` в UTC ISO 8601. `published_at`, `source_updated_at`, `occurred_at`, `last_success_at` могут быть `NULL`, если источник не предоставил дату. `created_at`, `updated_at`, `discovered_at` и `detected_at` задаются вызывающим кодом; триггеры не меняют время автоматически. Исходные заголовки и URL хранятся без перевода или перезаписи. Внешние ключи ограничивают удаление связанной истории.

Исключение: время ODA без установленного часового пояса хранится в исходном виде в метаданных, а `source_updated_at` остаётся `NULL`. Подробнее — [конвейер импорта](ingestion_pipeline.md).

Индексы поддерживают выборки по источнику, релевантности и дате публикации, историю событий по публикации/дате, очередь ожидающих уведомлений и состояние источников. Ограничения `UNIQUE` имеют собственные индексы и повторно не индексируются.

## Локальная проверка миграций

Для проверок используйте только флаг `--local`: Wrangler направляет запрос в локальное SQLite-хранилище, хотя в `worker/wrangler.jsonc` указан production D1 ID. Не запускайте команды с `--remote`, если не выполняете отдельно одобренную production-операцию.

```sh
cd worker
npx wrangler d1 migrations apply denmarktgbot-db --local
npx wrangler d1 execute denmarktgbot-db --local --command "SELECT name FROM sqlite_master WHERE type = 'table' ORDER BY name"
```

Не запускайте эти команды с `--remote`. Для будущих изменений добавляйте следующий SQL-файл с новой версией в `worker/migrations/`; уже применённую миграцию не редактируйте. `.wrangler/` и файлы SQLite исключены из Git.
